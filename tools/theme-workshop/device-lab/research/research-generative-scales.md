# Research: Generative Design-Token Scales + Intrinsic Layout Primitives in Tailwind v4

## Summary

A small set of CSS custom properties (base size, type-ratio, space-base, min/max viewport) can drive an
entire fluid type and space scale via `clamp()` math — generated by Utopia or hand-calculated — and fed
directly into Tailwind v4's `@theme` block. Every Layout's intrinsic primitives (Stack, Cluster, Sidebar,
Switcher, Grid) map cleanly to Tailwind utility classes or thin CSS components without breakpoints.
`round()` is now Baseline 2024 and enables crisp integer-px stepping for pixel fonts when paired with
`clamp()` and `cqi` container units.

---

## Findings

### 1. Modular Type Scale — the base × ratio^n formula

A modular scale assigns each typographic step a value computed as:

```
step(n) = base × ratio^n
```

Common ratios: Minor Third (1.2), Major Third (1.25), Perfect Fourth (1.333), Golden Ratio (1.618).

**Static CSS variables** (ratio = 1.25, base = 1rem):

```css
:root {
  --ratio: 1.25;
  --step--2: calc(1rem / var(--ratio) / var(--ratio));  /* 0.64rem */
  --step--1: calc(1rem / var(--ratio));                 /* 0.8rem  */
  --step-0:  1rem;
  --step-1:  calc(1rem * var(--ratio));                 /* 1.25rem */
  --step-2:  calc(1rem * var(--ratio) * var(--ratio));  /* 1.5625rem */
  --step-3:  calc(1rem * var(--ratio) * var(--ratio) * var(--ratio));
}
```

CSS custom property arithmetic can only chain multiply/divide, not use exponents directly, so steps must
be spelled out or generated by tooling (Utopia, SCSS, JS).

Source: [liminfo.com type scale tool](https://www.liminfo.com/tools/typescale),
[modularscale.com](https://www.modularscale.com/),
[Utopia CSS modular scales](https://utopia.fyi/blog/css-modular-scales/)

### 2. Utopia: Fluid Type + Space from ~5 Inputs

Utopia interpolates _two_ modular scales (one for the small viewport, one for the large viewport) and
generates a `clamp()` expression that transitions between them:

**Inputs**:
- `minWidth` / `maxWidth` — viewport poles (e.g. 320px / 1440px)
- `minFontSize` / `maxFontSize` — base at each pole (e.g. 16px / 20px)
- `typeScale` — ratio (e.g. 1.25 / 1.333 — can differ per pole for softer scaling on small screens)

**Output** (for each step n):

```css
:root {
  --step--1: clamp(0.83rem, calc(0.82rem + 0.08vw), 0.88rem);
  --step-0:  clamp(1.00rem, calc(0.92rem + 0.39vw), 1.25rem);
  --step-1:  clamp(1.20rem, calc(1.02rem + 0.88vw), 1.77rem);
  --step-2:  clamp(1.44rem, calc(1.11rem + 1.65vw), 2.50rem);
  --step-3:  clamp(1.73rem, calc(1.17rem + 2.80vw), 3.53rem);
  --step-4:  clamp(2.07rem, calc(1.17rem + 4.54vw), 5.00rem);
}
```

Space scale follows the same pattern; Utopia also generates "one-up" pairs (`--space-s-m`, `--space-m-l`)
for paired component gaps.

**Space output example**:

```css
:root {
  --space-3xs: clamp(0.25rem, calc(0.23rem + 0.11vw), 0.3125rem);
  --space-2xs: clamp(0.5rem, calc(0.46rem + 0.22vw), 0.625rem);
  --space-xs:  clamp(0.75rem, calc(0.69rem + 0.33vw), 0.9375rem);
  --space-s:   clamp(1rem, calc(0.92rem + 0.39vw), 1.25rem);
  --space-m:   clamp(1.5rem, calc(1.38rem + 0.58vw), 1.875rem);
  --space-l:   clamp(2rem, calc(1.85rem + 0.78vw), 2.5rem);
  --space-xl:  clamp(3rem, calc(2.77rem + 1.17vw), 3.75rem);
  --space-2xl: clamp(4rem, calc(3.69rem + 1.56vw), 5rem);
}
```

**Tooling**:
- Generator UI: [utopia.fyi](https://utopia.fyi/) — paste output directly into CSS
- PostCSS plugin: `postcss-utopia` — author `utopia.fluid()` calls in source, get clamp in output
- Tailwind plugin: [tailwind-utopia](https://github.com/cwsdigital/tailwind-utopia) — generates `text-step-1`, `gap-space-m` etc. (v3 syntax; needs adaptation for v4)
- SCSS mixin: [utopia-core-scss](https://github.com/trys/utopia-core-scss)

Sources: [Utopia blog/clamp](https://utopia.fyi/blog/clamp/), [Piccalilli Complete CSS lesson 7](https://piccalil.li/complete-css/lessons/7), [Smashing Magazine Utopia intro](https://www.smashingmagazine.com/2021/04/designing-developing-fluid-type-space-scales/)

### 3. Tailwind v4 `@theme` — Consuming CSS Custom Properties

Tailwind v4 treats `@theme` as the source of truth for all design tokens. Every variable defined there
becomes both a Tailwind utility and a native CSS custom property on `:root`.

**Key namespaces**: `--font-size-*` → `text-*`, `--spacing-*` → `p-*`/`m-*`/`gap-*`, `--color-*` → color utilities.

**Wire Utopia into Tailwind v4**:

```css
/* 1. Generate in :root (Utopia output, ungated) */
:root {
  /* === Generator inputs (informational) ===
     base:      16px → 20px
     type-ratio: 1.25 (sm) → 1.333 (lg)
     viewport:  320px → 1440px
  */
  --step--1: clamp(0.83rem, calc(0.82rem + 0.08vw), 0.88rem);
  --step-0:  clamp(1.00rem, calc(0.92rem + 0.39vw), 1.25rem);
  --step-1:  clamp(1.20rem, calc(1.02rem + 0.88vw), 1.77rem);
  --step-2:  clamp(1.44rem, calc(1.11rem + 1.65vw), 2.50rem);
  --step-3:  clamp(1.73rem, calc(1.17rem + 2.80vw), 3.53rem);
  --step-4:  clamp(2.07rem, calc(1.17rem + 4.54vw), 5.00rem);

  --space-xs: clamp(0.75rem, calc(0.69rem + 0.33vw), 0.9375rem);
  --space-s:  clamp(1rem, calc(0.92rem + 0.39vw), 1.25rem);
  --space-m:  clamp(1.5rem, calc(1.38rem + 0.58vw), 1.875rem);
  --space-l:  clamp(2rem, calc(1.85rem + 0.78vw), 2.5rem);
  --space-xl: clamp(3rem, calc(2.77rem + 1.17vw), 3.75rem);
}

/* 2. Map into Tailwind v4 @theme namespace */
@theme {
  /* Type */
  --font-size-xs:   var(--step--1);
  --font-size-base: var(--step-0);
  --font-size-lg:   var(--step-1);
  --font-size-xl:   var(--step-2);
  --font-size-2xl:  var(--step-3);
  --font-size-3xl:  var(--step-4);

  /* Spacing */
  --spacing-xs: var(--space-xs);
  --spacing-s:  var(--space-s);
  --spacing-m:  var(--space-m);
  --spacing-l:  var(--space-l);
  --spacing-xl: var(--space-xl);
}
```

Usage: `text-lg`, `gap-m`, `p-xl` — all fluid, zero breakpoints.

**Important caveat**: Tailwind v4 evaluates `@theme` values at build time for static utilities. When
`@theme` maps to a CSS variable (`var(--step-1)`), the clamp evaluation stays dynamic at runtime — this
works correctly but means the build can't pre-calculate responsive previews in tooling. Test in browser.

Sources: [Tailwind v4 @theme docs](https://tailwindcss.com/docs/theme), [Tailwind v4 release post](https://tailwindcss.com/blog/tailwindcss-v4), [font-size namespace docs](https://tailwindcss.com/docs/font-size)

### 4. Open Props — Generative CSS Variable System

Open Props ([openprops.style](https://open-props.style/)) ships a curated, opinionated set of CSS
custom properties covering size, color, font, animation, easing, and shadow — all on a deliberate scale.

**Scale shape** (sizing/spacing):
- `--size-1` through `--size-15` (geometric growth)
- `--font-size-0` through `--font-size-8` (fluid variants: `--font-size-fluid-1` etc.)
- Space-specific fluid: `--size-fluid-1` through `--size-fluid-10`

**Coexistence with Tailwind v4**: Open Props variables live on `:root` globally. You can map them into
Tailwind's `@theme` namespace selectively:

```css
@import "open-props/style";  /* or cdn; loads :root vars */

@theme {
  --font-size-sm:   var(--font-size-1);
  --font-size-base: var(--font-size-2);
  --font-size-lg:   var(--font-size-3);
  --spacing-s:      var(--size-fluid-2);
  --spacing-m:      var(--size-fluid-4);
  --spacing-l:      var(--size-fluid-6);
}
```

**Comparison to Utopia**:
| Dimension | Open Props | Utopia |
|---|---|---|
| Philosophy | Pre-baked curated scale | Math-derived from your inputs |
| Control | Import and use; limited customization | Full control from 5 inputs |
| Fluid values | Yes (fluid sub-set) | Yes (all values) |
| Tailwind fit | Good as primitives to alias | Best for systematic design tokens |
| Bundle size | Opt-in via PostCSS unused removal | Zero runtime; static output |

**Recommendation**: Use Utopia for systematic type + space scales. Adopt Open Props for supplementary
tokens (easing, shadow, border-radius, animation) that you haven't defined in your Utopia output.

Sources: [open-props.style](https://open-props.style/), [CSS-Tricks Open Props overview](https://css-tricks.com/open-props-and-custom-properties-as-a-system/), [nico.fyi Open Props + Tailwind](https://www.nico.fyi/blog/how-to-use-open-props-with-tailwind), [Modern CSS 2026 architecture](https://domainindia.com/support/kb/modern-css-tailwind-v4-open-props-cube-architecture)

### 5. `round()` — Crisp Integer-px for Pixel Fonts

**Browser support**: `round()`, `mod()`, `rem()` are **Baseline 2024** — all three major engines
(Chrome, Firefox, Safari) since May 2024. Safe to use without a fallback for modern targets.

Source: [MDN round()](https://developer.mozilla.org/en-US/docs/Web/CSS/round), [web.dev Baseline 2024 announcement](https://web.dev/blog/css-stepped-value-functions)

**Smooth vs stepped scales**:
- Smooth: `font-size: clamp(1rem, 2cqi, 2rem)` — sub-pixel values at every viewport width
- Stepped: `font-size: round(clamp(1rem, 2cqi, 2rem), 1px)` — snaps to nearest integer pixel

**For pixel-art / bitmap fonts**: sub-pixel sizes cause blurriness because the rasteriser can't align
glyph pixels to display pixels. Snapping to `1px` (or the device pixel ratio) keeps glyphs sharp.

```css
:root {
  /* Fluid base that snaps to whole pixels */
  --size-unit: round(clamp(12px, 1.5cqi, 20px), 1px);

  /* Derive a type scale from it — each step stays integer */
  --step-0: var(--size-unit);
  --step-1: round(calc(var(--size-unit) * 1.25), 1px);
  --step-2: round(calc(var(--size-unit) * 1.5625), 1px);
  --step-3: round(calc(var(--size-unit) * 1.953125), 1px);
}
```

**Grid snapping** (line-height, layout rhythm):

```css
.hero h1 {
  --grid-size: 4px;   /* or 0.25rem if rem-based */
  font-size: var(--step-3);
  line-height: round(calc(var(--step-3) * 1.2), var(--grid-size));
}
```

Source: [Ahmad Shadeed — Better fluid sizing with round()](https://ishadeed.com/article/css-round/),
[George Francis — Fluid Design with CSS round()](https://georgefrancis.dev/writing/fluid-design-with-css-round/),
[web.dev CSS stepped value functions](https://web.dev/blog/css-stepped-value-functions)

### 6. Container Query Length Units (`cqi`) as Fluid Anchor

`1cqi` = 1% of the nearest ancestor's **inline size** (horizontal in LTR).
Requires `container-type: inline-size` on an ancestor (body or a named container).

**Why `cqi` over `vw` for component-scoped fluid sizing**:
- `vw` always responds to the viewport — a sidebar card at 300px gets sizes calculated as if it were full-width
- `cqi` responds to the _container_ — component is self-contained and correct at any placement
- Aligns with the Korri principle: components respond to their container, not the viewport

**Usage pattern**:

```css
/* Page shell — single container at body level covers viewport-relative needs */
body {
  container-type: inline-size;
}

/* Component container — inner components respond to their own slot */
.card-grid > * {
  container-type: inline-size;
}

/* Fluid font from container width */
.card-grid .title {
  font-size: clamp(1rem, 3cqi, 1.5rem);
}
```

**As `@theme` base size** (experimental but viable):

```css
:root {
  container-type: inline-size;
  /* --base-unit tracks container width; clamp guards extremes */
  --base-unit: clamp(14px, 1.2cqi, 18px);
}

@theme {
  --font-size-base: var(--base-unit);
  --spacing-m:      calc(var(--base-unit) * 1.5);
}
```

Sources: [moderncss.dev CQI fluid typography](https://moderncss.dev/container-query-units-and-fluid-typography/),
[web.dev container queries and units](https://web.dev/articles/baseline-in-action-container-queries),
[CSS-Tricks cqi and cqb](https://css-tricks.com/container-query-units-cqi-and-cqb/)

### 7. Every Layout Intrinsic Primitives — Tailwind Mapping

Every Layout ([every-layout.dev](https://every-layout.dev/)) defines layout as composition of intrinsic
primitives that _naturally_ do the right thing without media queries.

| Primitive | Core Concept | Tailwind v4 mapping |
|---|---|---|
| **Stack** | `gap` between children in a flex column | `flex flex-col gap-[--space-m]` |
| **Cluster** | Wrapping flex row with consistent gap | `flex flex-wrap gap-[--space-s] items-center` |
| **Sidebar** | Side + main; main keeps min width, wraps below | `flex flex-wrap [&>:first-child]:basis-60 [&>:last-child]:basis-0 [&>:last-child]:grow [&>:last-child]:min-w-80` |
| **Switcher** | N columns until container too narrow, then stack | `flex flex-wrap [&>*]:basis-[calc((30rem-100%)*999)] [&>*]:grow` |
| **Grid (RAM)** | `repeat(auto-fit, minmax(MIN, 1fr))` | `grid grid-cols-[repeat(auto-fit,minmax(theme(--spacing-l),1fr))]` |
| **Center** | Max-width centered with padding | `mx-auto max-w-prose px-[--space-m]` |
| **Cover** | Fills height, centers principal child | `min-h-dvh grid [&>*]:my-auto` |

**Tailwind v4 plugin** (Tailwind v3 based, needs port):
- `tailwindcss-every-layout` npm package provides `stack`, `cluster`, `sidebar`, `switcher`, `cover`,
  `center` as utility classes backed by the spacing scale
- For v4, the cleanest approach is direct CSS components in `@layer components` using the patterns above

**Key insight**: The Switcher pattern is the most important for handheld-to-TV layouts. At a narrow
container it stacks; at wider it creates N columns — no media queries, no JS:

```css
@layer components {
  .switcher {
    display: flex;
    flex-wrap: wrap;
    gap: var(--space-m);
  }
  .switcher > * {
    /* negative threshold triggers wrap when container < 30rem */
    flex-basis: calc((30rem - 100%) * 999);
    flex-grow: 1;
  }
}
```

Sources: [every-layout.dev](https://every-layout.dev/), [every-layout.dev/layouts](https://every-layout.dev/layouts/),
[tailwind-every-layout plugin](https://tailwind-every-layout-plugin.netlify.app/layouts/),
[tailwindcss-every-layout npm](https://www.npmjs.com/package/tailwindcss-every-layout)

## Recommended Generator Set

A minimal parameter set that drives the entire scale:

```css
/* ============================================================
   SCALE PARAMETERS — edit only these ~8 values
   ============================================================ */
:root {
  /* Viewport poles */
  --vp-min: 320;       /* px, unitless for calc */
  --vp-max: 1440;      /* px, unitless for calc */

  /* Type base at each pole */
  --type-base-min: 16; /* px */
  --type-base-max: 20; /* px */

  /* Type ratio at each pole (different ratios = softer small scale) */
  --ratio-min: 1.2;    /* Minor Third — tight on handhelds */
  --ratio-max: 1.333;  /* Perfect Fourth — expressive on TV */

  /* Space multiplier relative to type base */
  --space-unit-min: 16; /* px — typically = type-base-min */
  --space-unit-max: 20; /* px */
}

/* ============================================================
   DERIVED SCALE — generated by Utopia or equivalent tool
   Paste fresh values here when parameters change.
   ============================================================ */
:root {
  /* Type steps (Utopia output) */
  --step--1: clamp(0.8333rem, 0.8152rem + 0.0905vi, 0.9375rem);
  --step-0:  clamp(1rem,      0.9565rem + 0.2174vi, 1.25rem);
  --step-1:  clamp(1.2rem,    1.0981rem + 0.5093vi, 1.6667rem);
  --step-2:  clamp(1.44rem,   1.2375rem + 1.0126vi, 2.2222rem);
  --step-3:  clamp(1.728rem,  1.3620rem + 1.8301vi, 2.9630rem);
  --step-4:  clamp(2.0736rem, 1.4613rem + 3.0613vi, 3.9506rem);

  /* Space scale (Utopia output) */
  --space-3xs: clamp(0.25rem, 0.2283rem + 0.1087vi, 0.3125rem);
  --space-2xs: clamp(0.5rem,  0.4565rem + 0.2174vi, 0.625rem);
  --space-xs:  clamp(0.75rem, 0.6848rem + 0.3261vi, 0.9375rem);
  --space-s:   clamp(1rem,    0.9130rem + 0.4348vi, 1.25rem);
  --space-m:   clamp(1.5rem,  1.3696rem + 0.6522vi, 1.875rem);
  --space-l:   clamp(2rem,    1.8261rem + 0.8696vi, 2.5rem);
  --space-xl:  clamp(3rem,    2.7391rem + 1.3043vi, 3.75rem);
  --space-2xl: clamp(4rem,    3.6522rem + 1.7391vi, 5rem);
  --space-3xl: clamp(6rem,    5.4783rem + 2.6087vi, 7.5rem);
}

/* ============================================================
   TAILWIND v4 @theme — maps generated vars to utilities
   ============================================================ */
@theme {
  /* Type */
  --font-size-xs:   var(--step--1);
  --font-size-sm:   var(--step-0);
  --font-size-base: var(--step-0);
  --font-size-lg:   var(--step-1);
  --font-size-xl:   var(--step-2);
  --font-size-2xl:  var(--step-3);
  --font-size-3xl:  var(--step-4);

  /* Spacing (maps to gap-*, p-*, m-*) */
  --spacing-3xs: var(--space-3xs);
  --spacing-2xs: var(--space-2xs);
  --spacing-xs:  var(--space-xs);
  --spacing-s:   var(--space-s);
  --spacing-m:   var(--space-m);
  --spacing-l:   var(--space-l);
  --spacing-xl:  var(--space-xl);
  --spacing-2xl: var(--space-2xl);
  --spacing-3xl: var(--space-3xl);
}

/* ============================================================
   PIXEL-FONT VARIANT — add when using bitmap/pixel typefaces
   round() snaps to nearest integer px → crisp rasterisation
   Requires: round() Baseline 2024 (Chrome/FF/Safari ≥ May 2024)
   ============================================================ */
.pixel-font {
  font-size: round(var(--step-0), 1px);
}
/* Or a stepped scale entirely in integer px: */
:root {
  --px-step-0: round(clamp(12px, 1.2cqi, 18px), 1px);
  --px-step-1: round(calc(var(--px-step-0) * 1.25), 1px);
  --px-step-2: round(calc(var(--px-step-0) * 1.5625), 1px);
}
```

**Workflow**:
1. Edit the 8 parameters in the "PARAMETERS" block.
2. Paste them into [utopia.fyi](https://utopia.fyi/) → copy the generated `:root {}` block.
3. Replace only the "DERIVED SCALE" section.
4. `@theme` bindings stay stable — do not change unless you rename tokens.

## Gaps

1. **Tailwind v4 + clamp in @theme: build-time vs runtime evaluation**. The docs don't explicitly
   specify whether `@theme { --foo: var(--bar); }` where `--bar` contains a `clamp()` is fully
   evaluated at runtime. Testing in a real Vite + Tailwind v4 build recommended before committing
   to the `@theme` aliasing approach. Alternative: use `@layer base { :root { --font-size-lg: var(--step-1); } }`
   and reference with Tailwind's arbitrary-value syntax `text-[var(--step-1)]`.

2. **tailwind-utopia for v4**. The existing `tailwind-utopia` npm plugin targets Tailwind v3's
   `theme.extend` config API. A v4-compatible equivalent using CSS-first `@plugin` or `@theme` has
   not been located in this search pass. May need manual implementation or the PostCSS approach.

3. **`round()` + `rem` units**. `round(clamp(1rem, 2cqi, 2rem), 1px)` mixes units — the browser
   must compute `rem` to px first then round. This works but behavior with user font-size overrides
   (accessibility scaling) needs verification; affected users may see jumpy text if their base rem
   differs from 16px. Consider `round(clamp(16px, 2cqi, 24px), 1px)` for pixel-font contexts to
   avoid rem ambiguity.

4. **`cqi` in nested containers**. When multiple ancestors have `container-type: inline-size`, `cqi`
   always resolves to the nearest ancestor's container, not the viewport. This is the desired
   behavior for component-scoped fluid sizing but can surprise when a component is used both
   top-level and nested. Needs a concrete design decision: one root container at body, or per-component.
