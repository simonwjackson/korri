# Preserve RetroArch spike config in repo and fix landed spike residuals

## Why it matters

The most valuable artifact from the local-emulation spike — the RetroArch lockdown config — exists only in /tmp on one workstation and on one tablet's filesystem. It encodes the entire "full control" thesis in 30 lines: the kiosk lockdown that makes RA invisible, the Korri-owned save paths, the runahead/rewind settings, and critically the GL driver line that is the difference between RA running and segfaulting on Mali hardware. A /tmp clear plus a tablet wipe destroys hours of hard-won findings. Separately, the spike code landed in main by accident (swept into an unrelated docs commit by a parallel session) carrying a comment that is now factually false, which will mislead the next reader.

## The config to preserve (recovery source of truth)

Lived at `/tmp/retroarch-korri.cfg` and on-device at `/sdcard/korri-retro/retroarch.cfg`:

```ini
# Generated by Korri — RA as headless emulation transport (spike)
# Every path RA touches lives in the Korri-owned tree.

libretro_directory = "/data/data/com.retroarch.aarch64/cores"
system_directory = "/storage/emulated/0/korri-retro/system"
savefile_directory = "/storage/emulated/0/korri-retro/saves"
savestate_directory = "/storage/emulated/0/korri-retro/states"
screenshot_directory = "/storage/emulated/0/korri-retro/screenshots"
playlist_directory = "/storage/emulated/0/korri-retro/playlists"
rgui_browser_directory = "/storage/emulated/0/korri-retro/roms"

# --- invisible RA: no menu reachable, no overlay, no OSD text ---
kiosk_mode_enable = "true"
input_menu_toggle_gamepad_combo = "0"
input_menu_toggle = "nul"
input_overlay_enable = "false"
video_font_enable = "true"

# --- session semantics: Korri owns the lifecycle ---
quit_on_close_content = "true"
config_save_on_exit = "false"
pause_nonactive = "true"

# --- seamless resume + kill-safety ---
savestate_auto_save = "true"
savestate_auto_load = "true"
autosave_interval = "10"

# --- remote control plane for the Korri shell (NO-OP: not compiled into the Android build) ---
network_cmd_enable = "true"
network_cmd_port = "55355"

# --- the features we refused to lose ---
rewind_enable = "true"
run_ahead_enabled = "true"
run_ahead_frames = "1"
run_ahead_secondary_instance = "true"
video_driver = "gl"

# --- debug (drop for production) ---
log_verbosity = "true"
frontend_log_level = "0"
libretro_log_level = "0"
```

Notes on specific lines:
- `video_driver = "gl"` — **load-bearing**. Stock Vulkan default SIGSEGVs in `font_driver_init_first` on Mali/Immortalis (Tab S10 Ultra). Without this, RA does not start at all.
- `config_save_on_exit = "false"` — keeps RA from mutating a Korri-authored config.
- `network_cmd_*` — verified no-op; the Android buildbot binary has no command interface compiled in. Kept for documentation and for when the fork lands.
- `video_font_enable` was flipped back to true during crash debugging; set to false for the invisible-RA production intent.

## Provisioning runbook to document

1. **RA buildbot APK ships zero cores** (assets contain only `.info` files and shaders). Cores must be installed once via Load Core → Install or Restore a Core, browsing `/sdcard/RetroArch/downloads/`. Obsolete once the fork bundles cores.
2. **Samsung/FUSE trap**: files pushed via adb into `/sdcard/RetroArch/downloads/` were invisible to RA's file browser (owned by a different uid, `chmod` ignored by FUSE) until a media scan plus time settled it. Not an issue in production, where the shell writes content through its own storage APIs — but a guaranteed time-sink for anyone repeating this by hand.
3. **Play Protect blocks adb sideload** of the RA APK: `INSTALL_FAILED_VERIFICATION_FAILURE`. Workaround used: `settings put global verifier_verify_adb_installs 0`, then restored to 1 afterwards.
4. **First launch takes ~60s** to extract assets; force-stopping mid-extraction produces an ANR and a broken state.
5. Test ROM used: `wl4.gba` (Wario Land 4), pushed to `/sdcard/korri-retro/roms/`.

## Also worth knowing

Observations during this spike were repeatedly corrupted by the tablet being in **Samsung DeX / desktop mode** (floating windows, "Desktop 1"), which produced black screencaps and confusing lifecycle behaviour. Exit DeX or reboot before trusting any lifecycle/rendering observation on that device.
